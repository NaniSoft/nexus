Nexus is the Agent Factory: a system that receives GitHub issues as use cases,
builds the change that answers them, and merges the result back to the
repository. One issue in, one reviewed pull request out.

It exists because agent-driven development is already powerful and already
produces real software — and because the way it happens today is ad hoc. A
person opens a terminal, picks a repository, writes a prompt, watches the run,
reviews the diff by hand, and pushes. Every step is manual, and none of it is
recorded anywhere a team can inspect. The work is real; the factory around it
is not.

Nexus is that factory. It watches configured repositories for issues, gives
every issue a fresh container to build in, lets coding agents do the work
inside it, and puts the result on a Kanban board where a human approves it,
asks for changes, or rejects it. Approval merges. Rejection closes the ticket.
Three rounds of feedback is the ceiling — after that the factory merges or
escalates rather than looping forever.

## The loop

1. **Poll** — the factory reads open issues from each configured repository and
   turns every one into a work item in the Backlog swimlane.
2. **Contain** — a fresh Docker container starts for the work item. Nothing
   carries over from a previous run.
3. **Build** — inside the container, [code-server](/docs/concepts/worker-containers)
   and OpenCode work the issue: planning, editing, running the tests.
4. **Review** — the result lands in the Review swimlane. A human approves,
   requests changes, or rejects.
5. **Merge** — approval opens and merges the pull request. Requested changes
   send the ticket back to the build with the feedback attached; three rounds
   maximum.

## Who it is for

Nexus is built for the maintainers of many repositories at once — the team that
has more issues than hands. Configuring a project is one YAML file in
`factories/`; after that the factory polls it, builds from it, and reports on
it alongside every other project, in round-robin order, without one project's
pipeline blocking another's.

## Status

Nexus is in active development. These docs describe the designed system in the
present tense: the architecture, the configuration model, the operational
posture, and the guarantees the design commits to. There is no quickstart here,
no screenshots, and no release notes — the factory has not shipped. The blog
follows the build as it happens.
